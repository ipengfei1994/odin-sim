## Overview

ODIN-Sim is the simulation platform of **ODIN — Opinion Dynamics with
Intelligent-agent Networks**, a research initiative focused on understanding how
opinions evolve through interactions among agents embedded in networks.

The platform provides the infrastructure for building, executing, and analysing
computational experiments over network structures, agent states, interaction
mechanisms, and opinion dynamics models. It is deliberately **not** tied to a
single dynamics model or agent implementation.

### Research workflow

**Model → Configure → Simulate → Analyze → Reproduce**

| Capability | What it means here | Status |
|---|---|---|
| Network modeling | `ba` / `er` / `ring` / `ws` / `sbm`, with optional stance-assortative rewiring | Available (see [assumptions](docs/topology-assumptions.md)) |
| Opinion dynamics | A registered model is executed by the engine; the platform does not hard-code any single model | Available via the G3 baseline adapter |
| Agent integration | Explicit interfaces for connecting external agent implementations | **Planned** — not yet implemented |
| Experiment management | Configuration, seeds, run metadata | Partial (single runs; sweep/runner **planned**) |
| Result analysis | Trajectories, aggregate metrics, cross-condition differences | Partial (metrics computed; analysis layer **planned**) |
| Reproducibility | Bit-exact regression against a reference dataset, environment and code snapshots | Available and verified |

<sub>Capabilities are marked as available only after implementation and
verification. Anything marked planned should not be assumed to exist.</sub>

### Project ecosystem

ODIN separates research modelling from execution infrastructure:

| Project | Responsibility |
|---|---|
| **ODIN-Sim** | Simulation infrastructure: networks, execution, experiment management, metrics, analysis |
| **odin-agents** | Agent implementations: behaviour, decision-making, memory, interaction strategies |

The two projects stay independently maintainable and communicate through
explicit interfaces. ODIN-Sim loads the G3 baseline from `odin-agents` **read-only
at runtime** — no source is copied into the dynamics kernel, and no file in
`odin-agents` is modified.

> **Boundary.** This repository contains only ODIN-Sim. Material belonging to
> `odin-agents` is kept outside version control (`docs/internal/`) and is never
> copied into the platform.

## Architecture

```text
                          ODIN-Sim
                              |
        +---------------------+---------------------+
        |                     |                     |
     Networks             Dynamics              Metrics
   topology/             model/protocol        model/registry
   ba er ring ws sbm     DynamicsModel         Metric
        |                     |                     |
        +---------------------+---------------------+
                              |
                    Simulation Engine
                    engine/runner.py
                    (dispatch · timing · assembly)
                              |
                    Experiment Runner        [planned]
                              |
              +---------------+---------------+
              |                               |
        Data & Metrics                  Run Metadata
        RunOutput                   reproducibility.py
        traj_hash / network_hash    commit · deps · config
              |                               |
              +---------------+---------------+
                              |
                     Analysis & Plots        [planned]
```

The layering rule is one-directional: the engine depends only on the **protocol**
(`model/protocol.py`), never on a concrete model. Models and metrics are resolved
through an explicit registry, and registering the same name twice is an error —
so an experiment cannot silently run on the wrong implementation.

A single run follows one path, with the model as the only writer of state:

```text
RunRequest ──► engine.run_once ──► DynamicsModel.run ──► RunOutput ──► Metric.compute
```

## Quick Start

### Requirements

- Python `>=3.12,<3.14` (developed and verified on 3.13.14)
- NumPy (numerical core); `uv` for environment management
- Optional: the G3 baseline from `odin-agents` — **only** needed to run or
  regress the G3 model

### Installation

```bash
git clone https://github.com/ipengfei1994/odin-sim.git
cd odin-sim

uv venv --python 3.13
uv sync --extra dev
```

### Generate a network

This needs no external project:

```python
from odin_sim.topology import build_network

net = build_network(n=500, seed=7, kind="ws")   # or: ba, er, ring, sbm
print(net["hash"], net["n_edges"], net["deg"].mean())
```

### Run a simulation

Requires the G3 baseline, loaded read-only at runtime:

```bash
export ODIN_BASELINE_ROOT=/path/to/odin-agents/baseline
```

```python
from odin_sim.engine import run_once
from odin_sim.model import DYNAMICS
from odin_sim.model.protocol import RunRequest

model = DYNAMICS.get("g3-baseline-v1")
record = run_once(model, RunRequest(
    mode="cross", placement="hub", beta_gov=0.20, tau=60, seed=7,
))
print(record.traj_hash, record.network_hash)
```

### Verify reproducibility

```bash
uv run pytest -q

uv run python -m odin_sim.cli verify-baseline \
    --data $ODIN_BASELINE_ROOT/data/g3_grid_runs.csv --scenario polarized

uv run python -m odin_sim.cli verify-metrics \
    --data $ODIN_BASELINE_ROOT/data/g3_grid_runs.csv --scenario polarized
```

## Experiments & Reproducibility

Reproducibility is a design requirement, not an afterthought. Every run is
expected to be identifiable and repeatable from explicit inputs.

| Element | How it is handled |
|---|---|
| Configuration | `RunRequest` carries mode, placement, dose, warm-up, scenario, seed, and parameter overrides — no implicit state |
| Randomness | Self-managed `SeedSequence`-derived generators; no global RNG is touched |
| Identifiers | `config_id = "{mode}_{placement}_b{beta:03d}_t{tau:02d}"` |
| Fingerprints | `traj_hash = sha1(round(traj, 10))[:16]`, `network_hash = sha1(src+dst)[:16]` |
| Environment | `odin-sim info` records commit, dirty flag, Python, platform, and dependency versions |
| Regression | 266 recorded runs are re-executed and compared **field by field** |

### Current verification status

| Check | Scope | Result |
|---|---|---|
| Trajectory fingerprint | 266 runs, `traj_hash` + `network_hash` | 266 / 266 identical, 0 mismatches |
| Metric equivalence | 266 runs × 25 fields | 266 / 266 identical, 0 mismatches |
| Topology parity | `ba` / `er` / `ring` vs the reference implementation | Bit-identical across seeds and homophily values |
| Injection safety | Running the baseline with the platform's topology injected | Trajectory fingerprints unchanged |
| Tests | Unit + regression | 40 passed |

Verified on Windows 11, Python 3.13.14, NumPy 2.3.4. NumPy is pinned because
network generation and initial conditions depend on the PCG64 stream; relaxing
the pin requires a cross-version study that has not been done.

<sub>These results establish that the platform **reproduces** the reference
baseline. They are not scientific findings about opinion dynamics.</sub>

## Roadmap

**Available**

- [x] Core configuration and run interfaces (`RunRequest` / `RunOutput`)
- [x] Network generation: `ba`, `er`, `ring`, `ws`, `sbm`
- [x] Protocol layer with an explicit registry for models, topologies, metrics
- [x] Execution engine (dispatch, timing, artefact assembly)
- [x] Controlled seeds and run metadata snapshots
- [x] Automated tests and a bit-exact baseline regression
- [x] Integration with the G3 baseline via a read-only runtime adapter

**In progress**

- [ ] Structured result storage and the analysis layer
- [ ] Batch experiment runner (sweeps over configurations and seeds)

**Planned**

- [ ] Public integration interface for `odin-agents`
- [ ] Platform-native opinion dynamics model (today only the adapter exists)
- [ ] Step-wise execution so external agents can act at each step
- [ ] Performance profiling before optimising any hotspot
- [ ] Interactive experiment visualisation

The roadmap is provisional and will be refined as research requirements become
clearer.
